# Plan 12b — Session Supervision — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With "General supervision" switched on, an academy assigns a supervisor (a staff member holding `session.supervise`) to subscriptions and sessions; the supervisor sees My supervision, opens a session from 10 minutes before its start until its end, and marks their own attendance. First, Plan 12a's open escalation finding is closed.

**Architecture:**
- **The switch.** `AcademySettings.supervision_enabled` (`db_default=False`). While it is off, the API sends no supervisor fields, every supervision route answers 404 and a `supervisor_id` in a subscription body is ignored; the stored values are kept.
- **Who may supervise.** `access.services.supervisors_queryset()` / `get_supervisor(id)`: active staff accounts holding `session.supervise` through an active role. Scheduling reaches it only through `access.services`.
- **The rules live in `etqan.scheduling.services.supervision`:**
  - generated sessions copy the subscription's supervisor;
  - a subscription change moves its unstarted sessions only;
  - one session can be overridden through the session PATCH, each field behind its own code;
  - Open and the supervisor's own attendance, on UTC instants.
- **The API.**
  - Subscription and session rows gain the supervisor fields for admins and staff, only while the switch is on; one settings read per request (`payloads.shows_supervision`).
  - `sessions/<id>/` gains PATCH.
  - `supervision/`, `supervision/<id>/open/`, `supervision/<id>/attendance/` and the pickers' `supervision/supervisors/` are new.
  - `session.supervise` joins `registry.IN_USE`, and the route table gains its rows.
- **The dashboard.**
  - Settings → Academy gains the "General supervision" switch.
  - The subscription form, its Edit dialog and summary, the session page and the sessions list show the supervisor while the switch is on.
  - My supervision (`/scheduling/supervision`) is a staff supervisor's own list, with its nav item.
- **Seeds and e2e.** `demo` has supervision on, with Sara supervising one subscription. The e2e journey: the admin switches supervision on and assigns Sara; Sara opens her session and marks herself present.

### Decisions this plan makes where the spec is silent or conflicts with the code

- **D1 — Who may supervise, and the pickers' list.**
  - A supervisor is an active staff account holding `session.supervise` through an active role (§3.5). `access.services.supervisors_queryset()` is that set, by name; `get_supervisor(id)` returns one or None. Admins are never supervisors: the spec says "a staff account", and an admin holds every code.
  - The pickers read `GET supervision/supervisors/` (`[{id, full_name}]`, by name, not paged: an academy has few). By Plan 12a D2's rule, a lookup that feeds a form takes the codes of the writes it feeds: any of `subscription.create`, `subscription.update` or `session.update`. It lives in scheduling, not `access/`: it answers 404 while the switch is off, and `access` may not import `academy`.
- **D2 — Routes and codes.** The spec writes `scheduling/supervision/…`; scheduling's routes are mounted at the API root (`sessions/`, `subscriptions/`), so these are `supervision/…` beside them.
  - `supervision/`, `supervision/<id>/open/` and `supervision/<id>/attendance/` declare `session.supervise`. They are not self-service: the code is what makes someone a supervisor, so `HasCode` checks it. An admin passes the check but supervises nothing: an empty list, and 404s.
  - `sessions/<id>/` PATCH declares any of `session.update` or `attendance.update`. The service then checks each field's own code, as §4.4 says: `supervisor_id` needs `session.update`, and `supervisor_attendance` needs `attendance.update` (403 on that field).
  - The subscription create and PATCH routes keep their codes; `supervisor_id` rides along.
  - `registry.IN_USE` gains `session.supervise`: the registry's in-use test and the route table's must-match test move with it.
- **D3 — Inheritance.**
  - Sessions take the subscription's supervisor when generated, now or later by the job.
  - A subscription change (`set_subscription_supervisor`) moves every session of that subscription that hasn't started (`starts_at > now`), whatever its status. A per-session override among them is overwritten too: the latest decision wins.
  - A moved session's `supervisor_attendance` goes back to `not_set` and `opened_by_supervisor_at` to null: they described the previous supervisor. Started sessions keep theirs.
  - The change is allowed only on an active or paused subscription (409 `scheduling.not_allowed_in_status`, like every subscription edit).
  - A renewal keeps the supervisor while they still may supervise, else none. Paused days generate no sessions, so there is nothing to move.
- **D4 — Open, attendance and the list (§4.4).**
  - Open is allowed while `starts_at − 10 min ≤ now < starts_at + minutes` (UTC instants), never on a cancelled session. It records `opened_by_supervisor_at` once, and returns `{meeting_url}` every time. Its refusals are 409s with codes.
  - The supervisor marks their own attendance, `present` or `absent`, from the moment the session opens and with no end, as teachers may mark late. Office users set any value, `not_set` included, through the session PATCH, with no time gate (like the admin's attendance undo); a session with no supervisor refuses anything but `not_set`.
  - My supervision lists the caller's sessions dated from the academy's today, **newest first** as §4.4 says (`-starts_at`), paged at 25, cancelled ones left out. Each row is the session row plus `can_open`. Another supervisor's session is a 404.
- **D5 — The switch off, and a supervisor who stops being one.**
  - Off: the supervisor fields are absent from every subscription and session payload, the supervision routes and the session PATCH answer 404 (after the permission check, so the route table's 403 rows hold), and a `supervisor_id` in a subscription body is ignored. The values stay stored; generation still copies them. Switching it on shows them again.
  - The fields go to admins and staff only: teachers, students and parents never see them (§4.4 speaks of the admin's views).
  - A supervisor who loses the code or is deactivated keeps their assignments. They can no longer reach the routes (403, or no sign-in); the pickers show them as "(can't supervise)"; assigning them anew is a 400.
- **D6 — Migrations.** `academy 0006` adds `supervision_enabled` (`db_default=False`). `scheduling 0005` adds the two FKs (nullable, `SET_NULL`, `related_name="+"`), `supervisor_attendance` (`db_default="not_set"`), `opened_by_supervisor_at` (nullable) and an index on `(supervisor, starts_at)` for My supervision. A test reads `information_schema` to pin the defaults.
- **D7 — Notifications.** None for supervisors (R-7: staff receive no notices); `etqan.notifications` is untouched.
- **D8 — Dashboard placement.**
  - Settings → Academy gains a "Supervision" fieldset with the "General supervision" checkbox.
  - The subscription create form shows a Supervisor select while the switch is on. The Edit dialog shows it, and the summary shows the supervisor, when the payload carries `supervisor` (it does only while the switch is on).
  - The session page gains a Supervision card: the Supervisor select (read-only name without `session.update`), the Supervisor attendance select (disabled without `attendance.update` or while no one is assigned), and when it was opened. The sessions list gains a Supervisor column (`Sara · Present`).
  - The "Supervisor attendance" control is on the session page only: §6.2 pairs it with the Supervisor select, but a subscription has no attendance of its own.
  - My supervision is `/scheduling/supervision` (`staticData.permission: "session.supervise"`), in a nav group "Supervision". It shows to a staff account holding `session.supervise` while the switch is on: `NavItem.feature` and `visibleNavItems(…, features)`. The app shell reads the settings only for such an account (`useAcademySettings({ enabled })`). Admins never see the item: they are never supervisors (D1).
  - The list re-reads each minute, so Open follows the clock; Open opens the meeting link in a new tab.
- **D9 — Seeds and the e2e journey.**
  - `seed_supervision` switches supervision on in `demo` and makes Sara the supervisor of Yusuf Omar's Tajweed subscription (her future sessions move to her), once. An academy where any subscription already has a supervisor is left alone, so switching it off in a dev database sticks; a missing Sara or subscription prints `skip:`. `other` gets neither.
  - The e2e journey:
    - the admin switches supervision off and on again (so the step is real on a seeded database);
    - they create a stamped student and a subscription with Sara, whose session today started five minutes ago;
    - Sara sets her password through "Forgot your password?" (her seeded invite renews, or a reset comes once she has a password) and signs in;
    - she opens the session from My supervision and marks herself present;
    - the admin's sessions list shows "Sara Supervisor · Present".
- **D10 — Plan 12a's open finding (Task 1).**
  - A staff editor may remove a role from a staff account only if it holds every code of that role, retired roles included and intersected with the registry: otherwise `403 {"role_ids": ["You can only remove roles whose permissions you hold yourself."]}`, and nothing is written.
  - Admins are unaffected. Keeping or resending roles is not a removal. Their own roles stay behind "You can't change your own roles.", which is checked first.
  - The check is `_guard_removed_roles` in `access.services`, next to `_roles_to_assign`.
- **D11 — Dashboard types.** `supervision_enabled` and the supervisor fields are optional in the TypeScript types (the server sends them only while the switch is on; a missing `supervision_enabled` reads as off), so the older fixtures need not spell them out.

opening a session, and the supervisor's own attendance.

The supervisor comes from ``access.services``: an active staff account
holding ``session.supervise`` through an active role. The academy's
"General supervision" switch only hides all of this from the API; the
values are kept while it is off."""

from datetime import timedelta

from django.db import transaction

from etqan.access import services as access_services
from etqan.platform.exceptions import ConflictError
from etqan.platform.exceptions import ForbiddenError
from etqan.platform.exceptions import NotFoundError

# §4.4: Open is allowed from this long before the start until the end.
OPENS_BEFORE = timedelta(minutes=10)
NOT_SET = Session.SupervisorAttendance.NOT_SET
MARKS = (Session.SupervisorAttendance.PRESENT, Session.SupervisorAttendance.ABSENT)
# The session PATCH's fields and the code a staff account needs for each
# (§4.4): assigning is a session update, the attendance an attendance one.
SESSION_FIELDS = {
    "supervisor_id": "session.update",
    "supervisor_attendance": "attendance.update",
}


def supervision_enabled() -> bool:
    """The academy's "General supervision" switch (R-6)."""
    return rules.settings().supervision_enabled


def supervisor_for(user_id: int | None):
    """The supervisor ``user_id`` names, None for None; any other id is a
    400 on ``supervisor_id``."""
    if user_id is None:
        return None
    supervisor = access_services.get_supervisor(user_id)
    if supervisor is None:
        raise ValidationError(
            "Choose an active staff member who can supervise.",
            field="supervisor_id",
        )
    return supervisor


def _unassigned() -> dict:
    """What a session's supervision fields go back to when its supervisor
    changes: the new supervisor hasn't come or opened it yet."""
    return {"supervisor_attendance": NOT_SET, "opened_by_supervisor_at": None}


@transaction.atomic
def set_subscription_supervisor(
    subscription: Subscription, *, supervisor_id: int | None
) -> Subscription:
    """§3.5: the subscription's supervisor, and that of its sessions that
    have not started (a per-session override among them too). Sessions that
    have started keep theirs. Locked and re-read like every subscription
    change, and only while it is active or paused."""
    supervisor = supervisor_for(supervisor_id)
    locked = Subscription.objects.select_for_update().get(pk=subscription.pk)
    rules.require_status(locked)
    if locked.supervisor_id == (supervisor.pk if supervisor else None):
        return locked
    locked.supervisor = supervisor
    locked.save(update_fields=["supervisor", "updated_at"])
    unstarted = (
        Session.objects.filter(subscription=locked, starts_at__gt=dates.now())
        .exclude(supervisor=supervisor)
        .order_by("pk")
        .select_for_update()
        .values_list("pk", flat=True)
    )
    Session.objects.filter(pk__in=list(unstarted)).update(
        supervisor=supervisor, updated_at=dates.now(), **_unassigned()
    )
    return locked


def _holds(by, code: str) -> bool:
    return code in codes_of(by)


@transaction.atomic
def update_session_supervision(session: Session, *, fields: dict, by) -> Session:
    """The session PATCH (§5.2): override one session's supervisor, or set
    the supervisor's attendance. Each field needs its own code (§4.4); a new
    supervisor starts with no attendance and unopened."""
    unknown = sorted(set(fields) - set(SESSION_FIELDS))
    if unknown:
        raise ValidationError("Unknown field.", field=unknown[0])
    for field, code in SESSION_FIELDS.items():
        if field in fields and not _holds(by, code):
            raise ForbiddenError("You can't change this.", field=field)
    locked = lock(session)
    changed = []
    if "supervisor_id" in fields:
        changed += _reassign(locked, fields["supervisor_id"])
    if "supervisor_attendance" in fields:
        changed += _set_attendance(locked, fields["supervisor_attendance"])
    if changed:
        locked.save(update_fields=[*dict.fromkeys(changed), "updated_at"])
    return locked


def _reassign(session: Session, supervisor_id: int | None) -> list[str]:
    supervisor = supervisor_for(supervisor_id)
    if session.supervisor_id == (supervisor.pk if supervisor else None):
        return []
    session.supervisor = supervisor
    for key, value in _unassigned().items():
        setattr(session, key, value)
    return ["supervisor", *_unassigned()]


def _set_attendance(session: Session, value: str) -> list[str]:
    if value not in Session.SupervisorAttendance.values:
        raise ValidationError(
            "Choose not set, present or absent.", field="supervisor_attendance"
        )
    if session.supervisor_id is None and value != NOT_SET:
        raise ValidationError(
            "Assign a supervisor first.", field="supervisor_attendance"
        )
    session.supervisor_attendance = value
    return ["supervisor_attendance"]


# ── The supervisor's own (§4.4) ──────────────────────────────────────────────


def supervised_sessions(user):
    """``user``'s sessions for today (the academy's calendar) and the
    upcoming ones, newest first (§4.4); cancelled ones are left out."""
    return (
        rules.sessions_queryset()
        .filter(supervisor=user, occurs_on__gte=rules.today())
        .exclude(status=Session.Status.CANCELLED)
        .order_by("-starts_at", "-id")
    )


def opens_at(session: Session):
    return session.starts_at - OPENS_BEFORE


def ends_at(session: Session):
    return session.starts_at + timedelta(minutes=session.minutes)


def can_open(session: Session) -> bool:
    """Open is allowed from 10 minutes before the start until the session
    ends (§4.4), on UTC instants, never a cancelled session."""
    now = dates.now()
    return session.status != Session.Status.CANCELLED and opens_at(
        session
    ) <= now < ends_at(session)


def _own(session: Session, *, by) -> Session:
    """The session's locked row, if it is ``by``'s to supervise; a 404
    otherwise, as for a session they can't see."""
    locked = lock(session)
    if by is None or locked.supervisor_id != by.pk:
        raise NotFoundError("Session", session.pk)
    if locked.status == Session.Status.CANCELLED:
        raise ConflictError(
            "This session was cancelled.", code="scheduling.session_cancelled"
        )
    if dates.now() < opens_at(locked):
        raise ConflictError(
            "The session opens 10 minutes before it starts.",
            code="scheduling.supervision_not_open",
        )
    return locked


@transaction.atomic
def open_session(session: Session, *, by) -> str:
    """§4.4 Open: the first opening is recorded once; the meeting link is
    returned each time, until the session ends."""
    locked = _own(session, by=by)
    if dates.now() >= ends_at(locked):
        raise ConflictError("This session has ended.", code="scheduling.session_ended")
    if locked.opened_by_supervisor_at is None:
        locked.opened_by_supervisor_at = dates.now()
        locked.save(update_fields=["opened_by_supervisor_at", "updated_at"])
    return locked.meeting_url


@transaction.atomic
def mark_supervisor_attendance(session: Session, *, by, status: str) -> Session:
    """§4.4: the supervisor marks their own attendance, present or absent,
    from the moment the session opens; later too, as teachers do."""
    if status not in MARKS:
        raise ValidationError("Choose present or absent.", field="status")
    locked = _own(session, by=by)
    locked.supervisor_attendance = status
    locked.save(update_fields=["supervisor_attendance", "updated_at"])
    return locked

/** Plan 12b §4.4, §6.2: the session's supervisor, their attendance and when
 * they opened it. The server sends these only while general supervision is
 * on, to admins and staff; the page shows this card only then. Assigning
 * needs `session.update`, the attendance `attendance.update`: without them
 * the values show, read-only. */
export function SessionSupervision({
	session,
	academyZone,
}: {
	session: Session;
	academyZone: string;
}) {
	const { t, i18n } = useTranslation();
	const can = useCan();
	const save = useSchedulingMutation(schedulingApi.updateSession);
	const assign = can("session.update");
	const mark = can("attendance.update") && session.supervisor != null;
	const onError = (error: unknown) =>
		toast({ description: errorText(error, t), variant: "destructive" });
	const opened = session.opened_by_supervisor_at;

	return (
		<Card>
			<CardHeader className="border-b border-border">
				<CardTitle>{t("scheduling.supervision.title")}</CardTitle>
			</CardHeader>
			<CardContent>
				<dl className="grid gap-4 sm:grid-cols-3">
					<Fact label={t("scheduling.supervision.supervisor")}>
						{assign ? (
							<Select
								aria-label={t("scheduling.supervision.supervisor")}
								value={session.supervisor?.id ?? ""}
								disabled={save.isPending}
								onChange={(e) =>
									save.mutate(
										{
											id: session.id,
											supervisor_id: e.target.value
												? Number(e.target.value)
												: null,
										},
										{ onError },
									)
								}
							>
								<SupervisorOptions current={session.supervisor} />
							</Select>
						) : (
							(session.supervisor?.full_name ??
							t("scheduling.supervision.none"))
						)}
					</Fact>
					<Fact label={t("scheduling.supervision.attendance")}>
						<Select
							aria-label={t("scheduling.supervision.attendance")}
							value={session.supervisor_attendance ?? "not_set"}
							disabled={!mark || save.isPending}
							onChange={(e) =>
								save.mutate(
									{
										id: session.id,
										supervisor_attendance: e.target
											.value as SupervisorAttendance,
									},
									{ onError },
								)
							}
						>
							{SUPERVISOR_ATTENDANCE.map((value) => (
								<option key={value} value={value}>
									{t(`scheduling.attendance.${value}`)}
								</option>
							))}
						</Select>
					</Fact>
					<Fact label={t("scheduling.supervision.opened")}>
						{opened ? (
							<>
								{dayIn(new Date(opened), academyZone, i18n.language)}{" "}
								<span dir="ltr">
									{wallTime(new Date(opened), academyZone, i18n.language)}
								</span>
							</>
						) : (
							t("scheduling.supervision.notOpened")
						)}
					</Fact>
				</dl>
			</CardContent>
		</Card>
	);
}

/** The options of a Supervisor select (Plan 12b §6.2): "No supervisor",
 * the current supervisor first (marked when they can no longer supervise,
 * so the value stays selectable while the list loads), then everyone else
 * who may. Mount it only for a viewer who may write what it feeds: that is
 * the code its list needs. */
export function SupervisorOptions({ current }: { current?: PersonRef | null }) {
	const { t } = useTranslation();
	const { data: supervisors } = useSupervisors(true);
	const others = (supervisors ?? []).filter((s) => s.id !== current?.id);
	const stillOne =
		supervisors === undefined || supervisors.some((s) => s.id === current?.id);
	return (
		<>
			<option value="">{t("scheduling.supervision.none")}</option>
			{current ? (
				<option key="current" value={current.id}>
					{stillOne
						? current.full_name
						: t("scheduling.supervision.cannotSupervise", {
								name: current.full_name,
							})}
				</option>
			) : null}
			{others.map((s) => (
				<option key={s.id} value={s.id}>
					{s.full_name}
				</option>

		new Date(`${day}T00:00:00Z`),

/** Five minutes ago on the demo academy's clock (UTC), or midnight in the
 * first five minutes of the day: today's session has started and has not
 * ended (45 minutes), so its Open window is open. */
function justStarted(now = new Date()): string {
	const earlier = new Date(now.getTime() - 5 * 60_000);
	if (earlier.getUTCDate() !== now.getUTCDate()) return "00:00";
	return earlier.toISOString().slice(11, 16);
}

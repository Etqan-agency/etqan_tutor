# Hosted Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve `docs/features/` and `docs/guide/` as a searchable Starlight site at
`docs.{$BASE_DOMAIN}` behind Caddy `basic_auth`, with a Switches page generated from the feature
registry.

**Architecture:** A new `docs-site/` Astro Starlight project in the meta repo loads Markdown in
place from `../docs` through a glob content loader. A small remark plugin rewrites links for the
site. A backend command `dump_features` writes the registry to a committed JSON file that the
Switches page renders, and CI fails when that file is stale. Production serves the static build
from nginx behind a new `docs.` site block in the Caddyfile.

**Tech Stack:** Astro 6 + `@astrojs/starlight` (Pagefind search), vitest, Django management
command, pytest, Caddy 2.11, nginx, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-30-docs-site-design.md`

## Global Constraints

- Only one copy of the docs: the site reads `docs/features/**` and `docs/guide/**` in place. Nothing is copied into `docs-site/`.
- Left out of the site: `docs/superpowers/`, `docs/kaleem-archive/` and the root `docs/*.md` audit files.
- The switches table comes from `REGISTRY`, never typed by hand.
- No path on `docs.{$BASE_DOMAIN}` (pages, `/pagefind/*`, `/_astro/*`) is served without `basic_auth`.
- Credentials are bcrypt hashes in a host file mounted into Caddy. They are never committed.
- `docs` is added to `RESERVED_SUBDOMAINS`.
- Submodule links (`backend/`, `dashboard/`, `marketing/`, `website/`, `infra/`, `tokens/`) go to `https://github.com/Etqan-agency/etqan_tutor_<name>/blob/main/<path>`. Links into `docs/superpowers/` go to `https://github.com/Etqan-agency/etqan_tutor/blob/master/docs/superpowers/<path>`.
- Pin every new dependency to an exact version. Starlight must be the newest release that supports Astro 6.
- Work on a `feat/docs-site` branch in the meta repo and a `feat/docs-site` branch in `backend/`. CI is billing-locked until 1 Nov 2026: gate merges on a local run of the `ci.yml` jobs this plan touches.
- The freshness pass (Task 7) is a separate track and does not block Tasks 1–6.

## Review Focus

1. **A missing or empty credentials file on the production host.** The deploy must stop with a clear message *before* Caddy reloads. It must never take down the academy edge. (Task 5: `ship.sh` preflight plus a test case in the infra-scripts tests.)
2. **A request to `docs.` for a static asset or the search index without credentials** → 401, the same as for a page. (Task 5: a `curl` check in the caddy CI job for `/pagefind/pagefind.js` and `/`.)
3. **An academy that already holds subdomain `docs`** before the reservation lands → the migration step reports it, and nothing gets silently shadowed. (Task 1: a test, plus a check you run once on production before deploying.)
4. **A doc link to a page that doesn't exist, or a switch whose `doc` slug has no page** → the docs build fails rather than shipping a 404. (Task 3 and Task 4: tests for the link check and the switches check.)
5. **A page with an anchor link (`sessions.md#postponement`) or a link to a guide page from a feature page (`../guide/testing.md`)** → resolves to the right site route with the anchor kept. (Task 3: plugin test cases.)

**Interfaces:**
